# DITA 0.2.0 — Checklist итерации 000

## Цель

Зафиксировать архитектуру чистого перезапуска DITA 0.2.0 и подготовить основание для первой схемы БД. Итерация 000 документальная: код, миграции и PostgreSQL не изменяются.

## Архитектура

- [x] DITA — платформа; GigaWatt — отдельная прикладная конфигурация.
- [x] Meta — ядро платформы.
- [x] Парадигма «платформа + конфигурация», ориентир 1С 7.7 без копирования внутренней реализации.
- [x] Модульный монолит: Go + PostgreSQL, pgx, явный SQL, `net/http`, `slog`.
- [x] Типизированные таблицы и колонки; EAV не используется как основное хранилище.
- [x] Первый функциональный результат — системное ядро и Meta.
- [x] Историческая документация и Git-история сохраняются.

## Модель данных

- [x] Внутренний `id bigint` отделён от бизнес-кода/номера.
- [x] Номер справочника начинается с 1 в пределах вида справочника.
- [x] Номер документа начинается с 1 в пределах вида документа и календарного года.
- [x] Номер плана начинается с 1 в пределах вида плана и календарного года.
- [x] Для документов/планов календарный год определяется по дате объекта в `Europe/Moscow`.
- [x] Нумерация атомарна, конкурентно-безопасна; выданные номера не переиспользуются.
- [x] Определены системные поля и правило `NULL` для отсутствующего actor без фиктивных ID.
- [x] Определены правила мягкого/физического удаления и каскада для композиционных данных.
- [x] Проведение и отмена проведения — отдельные транзакционные операции.
- [x] В стандартной метамодели предусмотрены Справочник, Документ, План, Задача и Заметка; реализация дополнительных подсистем не форсируется.

## Конфигурация и физическая схема

- [x] Конфигурация — версионируемый JSON.
- [x] Конфигурация декларативна; произвольный SQL и исполняемый код запрещены.
- [x] Каждый сохраняемый тип получает отдельную типизированную таблицу; реквизиты — типизированные колонки.
- [x] Физические имена основаны на стабильных технических идентификаторах.
- [x] Установка/обновление схемы — контролируемая отдельная операция; DDL не выполняется на обычных запросах.
- [x] Изменения схемы версионируются; разрушительные преобразования не генерируются автоматически.
- [x] Определены минимальная модель actor и граница Identity для первой итерации.

## Границы итерации 001

- [x] Перечень архитектурных решений, блокирующих схему, зафиксирован в `DECISIONS_DITA_0.2.0.md`.
- [x] Установлено, что точная SQL-реализация счётчиков, точная структура JSON и конкретные таблицы проектируются в итерации 001 без изменения архитектурных инвариантов.
- [x] Зафиксирован запрет автоматического переноса старой схемы.
- [x] Перед любым сбросом БД необходимо подтвердить точное имя целевой БД и исключить БД GigaWatt.
- [x] Подготовлен `CHECKPOINT_000.md` как финальный артефакт итерации.

## Критерии завершения

Итерация 000 считается документально завершённой: архитектура платформы и конфигурации зафиксирована; модель нумерации, системные поля, Identity-граница, формат конфигурации, физическое отображение метаданных, правила ссылок/удаления и жизненного цикла определены на уровне архитектуры; следующий шаг и ограничения зафиксированы в checkpoint.

## Ограничения

В итерации 000 не изменять исходный код, миграции, PostgreSQL, локальную БД или Git-историю. Не выполнять сброс БД без отдельного подтверждения её точного имени и плана безопасного действия. Не переносить старую схему автоматически и не включать сущности GigaWatt в ядро.
