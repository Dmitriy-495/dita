# DITA 0.1.0 — Iteration 002 Checklist

## Цель

Добавить PostgreSQL persistence для Meta-Layer `Catalog`.

## Задача

Спроектировать и реализовать минимальное хранение мета-описаний справочников в PostgreSQL.

## Scope

- [ ] Определить SQL-модель хранения `Catalog`.
- [ ] Определить необходимые PostgreSQL constraints.
- [ ] Создать migration.
- [ ] Реализовать repository для `Catalog`.
- [ ] Добавить создание `Catalog`.
- [ ] Добавить получение `Catalog`.
- [ ] Добавить обновление `Catalog`.
- [ ] Добавить тесты persistence.
- [ ] Проверить сохранение и чтение `id`, `name`, `prefix`.
- [ ] Проверить ошибки нарушения обязательных полей.
- [ ] Выполнить `gofmt`.
- [ ] Выполнить `go test ./...`.
- [ ] Выполнить `git diff --check`.
- [ ] Обновить архитектурную документацию.
- [ ] Создать `CHECKPOINT_002.md`.

## Границы

В Iteration 002 не входят:

- Runtime;
- HTTP API;
- динамические реквизиты;
- элементы справочника;
- генерация бизнес-кода;
- пользователи;
- системные реквизиты;
- soft delete;
- EAV;
- ORM;
- сущности GigaWatt-3.

## Критерий готовности

Meta-Layer `Catalog` должен храниться в PostgreSQL через типизированную модель и SQL-first repository без универсальной схемы хранения.

Следующий шаг определяется `CHECKPOINT_002.md`.
