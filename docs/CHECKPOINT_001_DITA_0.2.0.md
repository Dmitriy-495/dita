## Зафиксированная модель

1. Платформа DITA отдельно от конфигурации GigaWatt.
2. Стандартные виды: `catalog`, `document`, `planning`, `task`, `note`.
3. Общие поля самостоятельных объектов: `id`, `created_at`, `updated_at`, `created_by`, `updated_by`, `deleted_at`; `TIMESTAMPTZ` для временных полей.
4. `deleted_at` является каноническим soft-delete полем. Раннее `deletion_mark` признано устаревшим термином.
5. Минимальный `meta.actors` обеспечивает FK авторства и исполнителя Task; IAM не входит в объём.
6. Catalog code — BIGINT от 1 в пределах типа. Document/Planning number — BIGINT от 1 по типу и году, с транзакционным счётчиком и уникальными ограничениями.
7. Document и Planning используют календарный год `created_at` в `Europe/Moscow`; `number_year` фиксируется при создании и не меняется.
8. Task имеет обязательный assignee, ограниченный набор статусов и платформенный `completed_at`; просрочка не завершает задачу.
9. Note ограничена `description` и `important` сверх общих полей.
10. Конфигурация — строгий UTF-8 JSON v1, UUID-идентификаторы и SemVer.
11. Meta хранит конфигурации, версии, типы, атрибуты, actors и счётчики; прикладные типы создаются в схеме `data` отдельными типизированными таблицами.
12. Изменения конфигурации проходят dry-run; destructive changes не выполняются автоматически.
13. Ссылки — FK на конкретные типизированные таблицы; самостоятельные объекты по умолчанию RESTRICT; soft delete не каскадирует.
14. Проведение и отмена — отдельные транзакционные операции.

## Нерешённые вопросы, которые требуют фактической проверки/отдельного решения

- Точная локальная целевая БД и наличие данных; никаких DROP/CREATE/RESET не выполнять без отдельного подтверждения.
- Миграционный baseline чистой схемы DITA 0.2.0: старые migrations 000002/000003 нельзя считать автоматически применимыми к новой схеме.
- Безопасная стратегия перехода со строковых catalog codes на BIGINT, если данные требуется сохранить.
- Конкретные правила проведения прикладных документов/планов определяются конфигурацией; универсальные регистры не спроектированы.
- Фактический `git status` локального checkout неизвестен, поскольку локальный каталог пользователя недоступен из этой сессии.
